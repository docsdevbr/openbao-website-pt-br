# Autenticação por token

O método de autenticação `token` é integrado e está no núcleo da autenticação de
clientes.
Outros métodos de autenticação podem ser usados para autenticar um cliente, mas
eles eventualmente resultam na geração de um token de cliente gerenciado pelo
backend `token`.

Cada token possui diversas propriedades:

- ID - O ID principal de um token é um valor gerado aleatoriamente.
- Nome de exibição - Opcionalmente, um nome de exibição legível para pessoas.
- Metadados - Metadados usados para registro de auditoria.
- Número de usos - Opcionalmente, uma contagem de usos restritos.
- ID do token pai - Opcionalmente, um token pai que criou este token filho.
- Políticas - Uma lista associada de políticas ACL.
- Caminho de origem - O caminho no qual o token foi gerado (por exemplo,
  `auth/github/login`).

As propriedades de um token são imutáveis após a criação.
A exceção a isso é o número de usos, que é decrementado a cada requisição.
Cada uma dessas propriedades permite que o OpenBao faça uma série de coisas
interessantes.

Cada token mantém o caminho de origem, ou o caminho de login, usado para criar o
token.
Isso é usado para permitir a revogação baseada na origem.
Por exemplo, se acreditarmos que nossa organização do GitHub foi comprometida,
podemos querer revogar todos os tokens gerados via `auth/github/login`.
Isso seria feito usando a API `sys/revoke-prefix/` com o prefixo `auth/github/`.
Revogar o prefixo revogará todos os tokens de cliente gerados nesse caminho, bem
como todos os segredos dinâmicos gerados por esses tokens.
Isso fornece um poderoso procedimento de "quebra de vidro" durante uma possível
invasão.

Se um token for criado por outro método de autenticação, ele não terá um token
pai.
No entanto, quaisquer tokens criados pela API `auth/token/create` têm um token
pai, ou seja, o token usado para fazer essa requisição.
Ao manter essa relação pai-filho, o OpenBao modela árvores de tokens.
Tokens filhos podem ser criados com um subconjunto das políticas do pai,
permitindo a remoção de privilégios.
Quando um token é revogado, toda a subárvore de tokens é revogada com ele.
Isso permite que os clientes gerem tokens filhos com segurança e, em seguida,
revoguem todos eles, juntamente com a raiz.

Tokens filhos são muito úteis, especialmente quando combinados com tokens de uso
limitado.
Quando um token é criado, sua contagem de usos pode ser especificada
opcionalmente.
Fornecer uma contagem de usos igual a um cria um _token de uso único_.
Isso significa que o token pode ser usado para uma única requisição antes de ser
revogado automaticamente.
Isso pode ser generalizado para qualquer número de usos.
Tokens de uso limitado não podem ser usados para criar subtokens, mas podem ser
uma maneira poderosa de permitir acesso extremamente limitado ao OpenBao.
